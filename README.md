# WeMai

WeMai 是面向 MaiBot、微信 4.1.9.30 和 WeFlow 的 Windows 一体化适配器。本项目由 AI 参与整合与优化，仅供学习和技术研究，不可用于商业用途；第三方组件继续遵循各自许可证。

- 入站：WeFlow 推送全部微信消息，WeMai 不再维护群聊黑白名单。
- 合并记录：自动展开文本、链接标题/描述/URL、媒体说明和嵌套聊天记录；微信未提供实体的原生语音会显示时长说明。
- 身份：始终以 WeFlow 的真实 `session_id` 作为会话唯一标识。
- 出站：文本、图片、文件和语音均由 WeMai 发送到独立聊天窗口。
- 语音：内置 VoiceHost，通过 VB-CABLE 播放并驱动微信录音；长音频自动按最多 60 秒分段。
- 配置：本机 WebUI，默认地址 `http://127.0.0.1:8888`。
- 运维：首次启动自动创建 `.venv`、检查并安装依赖，核心异常后自动重启。

## 快速开始

1. 安装并登录微信 `4.1.9.30`，保持微信进程运行，不要锁屏或休眠。WeMai 启动时会自动恢复主窗口。
2. 部署并启动 WeFlow 和 MaiBot。
3. 在 MaiBot 的 `config/bot_config.toml` 中把 `platform` 设为 `wx`，机器人账号也使用 `wx:机器人微信昵称或wxid`。
4. 需要发送语音时安装 [VB-CABLE](https://vb-audio.com/Cable/)，将 `CABLE Output` 设为微信麦克风。VoiceHost 会自动选择 `CABLE Input` 播放。
5. 只需要消息收发和语音时使用核心版；需要联系人或群管理时使用完整版。解压 WeMai 后双击 `Start-WeMai.vbs`，启动器只创建一个正式控制台，不会闪出临时 CMD 窗口。
6. 首次启动会自动安装 Python 依赖，命令行随后显示 WebUI 访问地址。浏览器打开该地址，填写 WeFlow Token 等信息，保存后点击“重启 WeMai”。

电脑需安装 64 位 Python 3.9 或更高版本并加入 `PATH`。VoiceHost 和高级扩展均为自包含程序，目标机无需单独安装 .NET。

完整安装、配置、语音、群管理、故障恢复和参考项目说明见 [WeMai-Manual.md](WeMai-Manual.md)。
源码结构、线程边界和不可破坏的并发约束见 [代码维护指南.md](代码维护指南.md)。

## 工作方式

WeFlow 的真实 ID，例如 `45808329857@chatroom` 或 `wxid_xxx`，在用户修改昵称、群昵称或群名后不会改变。WeMai 用这个 ID 绑定独立窗口句柄；微信已打开的独立窗口标题不会刷新，因此绑定在窗口关闭或 WeMai 停止前保持不变。新名称由 WeFlow 推送给 MaiBot，MaiBot 的聊天流 ID 不变。

WeMai 启动时只自动恢复微信主窗口，不会预先打开任何聊天独立窗口。首次给某个会话发送消息时，WeMai 才优先从会话列表打开正确的独立窗口，列表中不存在时使用兼容搜索兜底。每次粘贴搜索词后固定等待 3 秒，最多搜索两次；仍未找到时仅让该目标进入冷却，不影响其他会话。后续发送直接复用真实 ID 对应的窗口句柄；已绑定窗口意外消失后，会按真实 ID 对应的最新名称自动重开并换绑新 HWND。

群名或私聊昵称修改后，WeFlow 继续推送同一个真实 ID 和新的显示名称。MaiBot 使用真实 ID 保持原聊天流，WeMai 则让真实 ID 继续绑定原独立窗口 HWND，不检查已经过期的窗口标题。只有该 HWND 关闭或 WeMai 停止/重启后才解除绑定。

WeMai 对外平台标识固定为 `wx`。适配器和 MaiBot 两端必须完全一致；`wx4py` 只是内部依赖名称，不能再作为机器人平台名。旧版从 `wx4py` 改到 `wx` 后，MaiBot 会按新平台键识别身份，正式切换前应确认 MaiBot 配置已经同步修改。

系统提醒保留原始正文，不添加 `[系统消息]` 前缀；能从 WeFlow 明确还原操作者时
复用该用户身份，否则使用独立的“微信系统消息”虚拟身份，不污染真实群成员。

## WebUI

默认仅监听 `127.0.0.1:8888`。可在配置中心修改监听地址和端口；使用 `0.0.0.0` 或其他非回环地址时必须设置访问密码。

WebUI 可配置：

- WeFlow API 地址和 Token
- MaiBot WebSocket 地址和数据目录
- MaiBot 平台标识（固定为 `wx`）
- 机器人微信昵称、媒体目录、日志级别
- 联系人管理、群管理高级扩展
- WebUI 地址、端口和访问密码
- 保存配置，启动、停止和重启 WeMai

配置保存后再次打开会重新从 `.env` 读取普通字段。Token 和密码不会回传明文，页面以“已保存”状态显示；留空保存表示保持原值。停止只关闭核心服务，WebUI 和监督器继续运行；启动会使用已保存配置重新拉起核心；重启会先安全停止核心、重新读取 `.env`，再在原命令行窗口内启动。

联系人和群管理默认关闭。两项全部关闭时不会启动 WeChatAuto.SDK 高级宿主，也不会加载 OCR 模型，不影响核心消息收发性能。核心版不包含约 300 MiB 的高级宿主，WebUI 会禁用对应开关；完整版保留全部联系人和群管理能力。群管理的连接方法和调用示例见 `WeMai-Manual.md`；朋友圈属于上游 VIP 能力，不包含在 WeMai 社区版中。

## 语音约束

- 支持 MP3 和 WAV，单文件默认不超过 15 MiB。
- 微信电脑端单次录音上限约一分钟，WeMai 将长音频自动拆成最多 60 秒的片段依次发送。
- 音频格式和时长先校验，之后才进入全局 UI 独占。
- 音频校验和独立窗口解析不占用全局独占；窗口解析成功后、按下右 Alt 前进入独占，到释放右 Alt 并确认发送后结束。
- 语音使用微信原生右 Alt 模式：按下后立即播放，播放结束释放并发送；不增加固定等待或静音，之后必须确认界面恢复“发语音”状态。
- 小于 1 秒的音频会被微信拒绝，WeMai 会在操作 UI 前直接拒绝。
- 每个语音片段录制期间其他出站消息等待；片段结束后文本、图片和文件优先发送，再继续下一段。
- 已成功发送部分片段后若后续失败，只记录不可自动重放的诊断死信，避免重复发送前面的片段。

## 日志

运行日志默认写入根目录 `wemai.log`。WeMai 启动时会从现有微信进程恢复主窗口，但不读取、展开或点击系统托盘，也不会预开聊天独立窗口；请在启动前登录微信并保持微信进程运行。仅在产生实际退出诊断时才会创建 `wemai_exit.log`，正常运行期间不会留下空文件。排查问题时优先查看：

通过 `Start-WeMai.vbs` 启动后，按 `Ctrl+C` 会显示中文关闭确认。输入 `Y` 后核心进程先关闭全部可验证的微信独立聊天窗口、最小化主窗口，再退出；输入 `N` 或直接回车则继续运行。

- VoiceHost 是否找到 `CABLE Input`
- WeFlow Token 和 API 是否可用
- MaiBot WebSocket 是否连接
- 微信版本是否为 4.1.9.30，主窗口和账号是否已登录
- 独立窗口是否被人工关闭，或发送时鼠标键盘是否抢占微信焦点
